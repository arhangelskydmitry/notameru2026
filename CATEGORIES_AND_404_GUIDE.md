## 🎯 Практические сценарии использования

### Сценарий 1: Массовая категоризация после миграции

**Проблема:** После переноса сайта 200 статей остались без категорий.

**Решение:**
```
1. Открыть assign-default-category.php

3. Выполнить → все статьи получили категорию "Новости"
4. Время: 5 секунд
```

**До:**
```
200 статей без категорий
→ не показываются в рубриках
→ плохо для SEO
```

**После:**
```
200 статей в категории "Новости"
→ отображаются в рубрике
→ улучшено SEO
```

## 📊 Что логируется

### Данные в таблице `not_found_logs`

```sql
id              - Уникальный идентификатор
url             - Полный URL (с параметрами)
referer         - Откуда пришел пользователь
ip_address      - IP адрес
user_agent      - Браузер и ОС
method          - GET/POST
created_at      - Дата и время
```

### Что НЕ логируется (исключения):

```
✗ /notaadmin/*        - админка
✗ /wp-admin/*         - WordPress админка
✗ /wp-includes/*      - служебные файлы WP
✗ /wp-content/*       - контент WP
✗ favicon.ico         - иконка сайта
✗ robots.txt          - файл для поисковиков
✗ sitemap.*           - карты сайта
✗ *.xml, *.json       - служебные файлы
✗ apple-touch-icon    - иконки для iOS
```

**Зачем исключения:** Чтобы не засорять логи техническими запросами.

## 🛠️ Техническая информация

### Структура таблицы БД

```sql
CREATE TABLE `not_found_logs` (
  `id` bigint unsigned AUTO_INCREMENT PRIMARY KEY,
  `url` varchar(500) NOT NULL,
  `referer` varchar(500) NULL,
  `ip_address` varchar(45) NULL,
  `user_agent` varchar(500) NULL,
  `method` varchar(10) DEFAULT 'GET',
  `created_at` timestamp DEFAULT CURRENT_TIMESTAMP,
  
  INDEX `url_index` (`url`),
  INDEX `created_at_index` (`created_at`),
  INDEX `url_created_at_index` (`url`, `created_at`)
) ENGINE=InnoDB CHARSET=utf8mb4;
```

---

### API эндпоинты (404 логи)

```
GET  /notaadmin/404-logs
     → Главная страница статистики
     Параметры: ?period=7

GET  /notaadmin/404-logs/details
     → Детали конкретного URL
     Параметры: ?url=/path&period=30

POST /notaadmin/404-logs/cleanup
     → Очистка старых логов
     Параметры: days=90

GET  /notaadmin/404-logs/export
     → Экспорт в CSV
     Параметры: ?period=30
```

---

### Методы модели NotFoundLog

// Логировать 404

## 🎓 FAQ

**Q: Можно ли изменить категорию в скрипте?**

```php
// В файле assign-default-category.php, строка 36
$DEFAULT_CATEGORY_NAME = 'Новости'; // Изменить на нужную
```

**Q: Скрипт назначит категорию дважды?**

A: Нет, есть проверка существования связи. Повторно не назначит.

**Q: Как часто очищать логи 404?**

A: Рекомендуется раз в 90 дней. Зависит от трафика сайта.

**Q: Логируются ли боты?**

A: Да, все запросы логируются. User Agent позволяет отличить ботов.

**Q: Можно ли отключить логирование 404?**

A: Да, удалить `Log404Errors::class` из `bootstrap/app.php`.

**Q: Влияет ли логирование на скорость сайта?**

A: Минимально, добавляет 2-3 мс к времени ответа 404.

**Q: Можно ли создать редиректы из админки?**

A: Пока нет, но можно добавить эту функцию в будущем.
