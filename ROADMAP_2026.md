### 2. 🏷️ Редактирование Тегов

**Цель:** Полноценное управление тегами для организации контента.

#### 2.1 CRUD Операции
```
📁 Модуль: app/Http/Controllers/TagController.php
📁 Маршруты: routes/web.php (admin/tags)
📁 Представления: resources/views/admin/tags/
📁 Таблица БД: wp_terms, wp_term_taxonomy (taxonomy='post_tag')
```

**Функции:**
- **Список тегов:**
  - Таблица с колонками: ID, Название, Slug, Описание, Количество статей, Действия
  - Поиск по названию
  - Сортировка (по имени, количеству статей, дате создания)
  - Пагинация

- **Создание тега:**
  - Название (обязательное)
  - Slug (автогенерация, редактируемый)
  - Описание (необязательное)

- **Редактирование тега:**
  - Изменение названия, slug, описания
  - Список статей с этим тегом (с ссылками)

- **Удаление тега:**
  - С подтверждением
  - Предупреждение о количестве статей, где используется
  - Опция: удалить связи или переназначить на другой тег

#### 2.2 Объединение Тегов (Merge)
- **Функционал:**
  - Выбор нескольких тегов для объединения
  - Целевой тег (куда объединить)
  - Автоматическое переназначение всех статей на целевой тег
  - Удаление исходных тегов после объединения
  - Обновление счетчиков

#### 2.3 Массовые Операции
- **Действия:**
  - Выбор нескольких тегов (чекбоксы)
  - Массовое удаление
  - Массовое изменение (добавить префикс/суффикс к slug)

#### 2.4 Статистика Тегов
- **Информация:**
  - Топ-10 самых используемых тегов
  - Неиспользуемые теги (0 статей)
  - Теги с одной статьей (кандидаты на удаление или объединение)

#### 2.5 SEO Настройки для Тегов
- **Поля:**
  - SEO Title (для страницы архива тега)
  - Meta Description
  - OG:title, OG:description, OG:image
  - Noindex/Nofollow (для фильтрации малозначимых тегов)

**Приоритет:** 🔶 СРЕДНИЙ  
**Сложность:** ⭐⭐ (средняя)  
**Оценка:** ~10-15 часов разработки

### 3. 📂 Файловый Менеджер

**Цель:** Управление медиафайлами через удобный веб-интерфейс.

#### 3.1 Основной Функционал
```
📁 Модуль: app/Http/Controllers/FileManagerController.php
📁 Маршруты: routes/web.php (admin/files)
📁 Представления: resources/views/admin/file-manager/
📁 Директории: public/uploads, public/wp-content/uploads, public/images
```

**Возможности:**
- **Просмотр файлов:**
  - Древовидная структура папок (слева)
  - Сетка или список файлов (справа)
  - Превью для изображений (thumbnail)
  - Иконки для других типов файлов (PDF, DOC, ZIP)
  - Информация: имя, размер, дата загрузки, размеры (для изображений)

- **Загрузка файлов:**
  - Drag-and-drop в интерфейс
  - Множественная загрузка
  - Прогресс-бар для каждого файла
  - Ограничения по размеру и типу (настраиваемые)
  - Автоматическая оптимизация изображений (resize, компрессия)
  - Генерация WebP версий

- **Управление файлами:**
  - Переименование
  - Копирование/перемещение в другую папку
  - Удаление (с подтверждением)
  - Скачивание
  - Копирование ссылки (URL) в буфер обмена

- **Управление папками:**
  - Создание новой папки
  - Переименование папки
  - Удаление папки (если пустая или с подтверждением)
  - Перемещение папки

#### 3.2 Расширенные Функции
- **Поиск:**
  - По имени файла
  - По типу (изображения, документы, архивы)
  - По дате загрузки
  - По размеру файла

- **Фильтры:**
  - Только изображения
  - Только неиспользуемые файлы (не привязаны к статьям)
  - Файлы больше X МБ

- **Статистика хранилища:**
  - Общий размер всех файлов
  - Разбивка по типам файлов (изображения 80%, документы 15%, прочее 5%)
  - Список самых больших файлов (топ-10)
  - Неиспользуемые файлы (кандидаты на удаление)

#### 3.3 Интеграция с Редактором
- **Вставка в статью:**
  - Кнопка "Добавить медиа" в редакторе статьи
  - Модальное окно с файловым менеджером
  - Выбор файла → автоматическая вставка в контент
  - Для изображений: выбор размера (thumbnail, medium, large, full)

#### 3.4 Обработка Изображений
- **Встроенный редактор:**
  - Обрезка (crop)
  - Изменение размера (resize)
  - Поворот
  - Наложение водяного знака (опционально)
  - Настройка яркости, контраста, насыщенности

- **Автоматические миниатюры:**
  - Генерация нескольких размеров при загрузке (150x150, 300x300, 600x400, 1200x800)
  - Настраиваемые размеры в конфигурации

#### 3.5 Права Доступа
- **Роли:**
  - SuperAdmin: полный доступ ко всем файлам
  - Editor: доступ к своим файлам и файлам в общей папке
  - Author: только свои файлы

**Приоритет:** 🔶 СРЕДНИЙ  
**Сложность:** ⭐⭐⭐⭐ (высокая)  
**Оценка:** ~30-40 часов разработки

### 4. 💾 Автоматические Бекапы и Скачивание через Админку

**Цель:** Автоматизировать резервное копирование и упростить восстановление.

#### 4.1 Автоматические Бекапы
```
📁 Модуль: app/Console/Commands/AutoBackup.php
📁 Крон: app/Console/Kernel.php (schedule)
📁 Контроллер: app/Http/Controllers/BackupController.php
📁 Представления: resources/views/admin/backups/
📁 Хранилище: storage/backups/ или настраиваемое
```

**Функционал:**
- **Расписание:**
  - Настраиваемое расписание через CRON или Laravel Scheduler
  - Ежедневно в заданное время (например, 03:00 по МСК)
  - Еженедельно (выбор дня недели)
  - Ежемесячно (выбор даты)

- **Что бекапится:**
  - Полный дамп БД (MySQL)
  - Файлы из `public/uploads`, `public/wp-content/uploads`, `public/images`
  - Конфигурация: `.env`, `config/*.php`, `seo-settings.json`
  - Опция: весь код приложения (для полного восстановления)

- **Формат бекапа:**
  - `.tar.gz` архив
  - Имя файла: `backup-YYYY-MM-DD-HH-MM.tar.gz`
  - Manifest внутри архива (список файлов, дата, версия Laravel)

- **Ротация бекапов:**
  - Хранить последние N бекапов (по умолчанию 7)
  - Автоматическое удаление старых бекапов
  - Особая политика: хранить один бекап за каждый месяц (долгосрочный архив)

#### 4.2 Хранилища Бекапов
- **Локальное хранилище:**
  - `storage/backups/` на сервере
  - Настройка лимита размера (предупреждение при превышении)

- **Удаленное хранилище (опционально):**
  - Yandex.Disk (API интеграция)
  - Google Drive
  - Dropbox
  - S3-совместимое хранилище (например, VK Cloud)
  - FTP/SFTP сервер

- **Настройки:**
  - Выбор основного и резервного хранилища
  - Автоматическая загрузка бекапа после создания

#### 4.3 Веб-интерфейс Управления Бекапами
- **Список бекапов:**
  - Таблица: Дата, Размер, Тип (авто/ручной), Место хранения, Действия
  - Фильтр по дате и типу

- **Действия:**
  - 🔽 **Скачать** - скачать бекап на локальный компьютер
  - 🔄 **Восстановить** - восстановление из бекапа (с подтверждением и предупреждением)
  - 🗑️ **Удалить** - удаление бекапа
  - 📋 **Информация** - детали бекапа (список файлов, размер БД, версия)

- **Создание бекапа вручную:**
  - Кнопка "Создать бекап сейчас"
  - Выбор: только БД / только файлы / полный
  - Прогресс-бар (AJAX)
  - Уведомление по завершении

#### 4.4 Восстановление из Бекапа
- **Мастер восстановления:**
  - Шаг 1: Выбор бекапа
  - Шаг 2: Предпросмотр содержимого (список файлов, таблиц БД)
  - Шаг 3: Выбор компонентов для восстановления (БД / файлы / конфигурация)
  - Шаг 4: Подтверждение (с предупреждением о перезаписи)
  - Шаг 5: Прогресс и результат

- **Безопасность:**
  - Автоматическое создание бекапа текущего состояния перед восстановлением
  - Тестирование целостности бекапа перед восстановлением
  - Лог всех операций восстановления

#### 4.5 Уведомления
- **События:**
  - Успешное создание бекапа (логирование, опционально email)
  - Ошибка при создании бекапа (email суперадмину)
  - Нехватка места на диске (предупреждение)
  - Устаревшие бекапы (удалены по ротации)

- **Каналы:**
  - Email (для суперадминов)
  - Внутренние уведомления в админке
  - Telegram бот (опционально, интеграция)

#### 4.6 Настройки Бекапов
- **Конфигурация:**
  - Включить/выключить автобекапы
  - Расписание (время, день недели)
  - Количество хранимых бекапов
  - Что бекапить (БД, файлы, конфиг, код)
  - Место хранения (локально, удаленно)
  - Email для уведомлений
  - Исключения (папки/файлы, которые не нужно бекапить)

**Приоритет:** 🔥 ВЫСОКИЙ  
**Сложность:** ⭐⭐⭐ (средняя-высокая)  
**Оценка:** ~20-30 часов разработки

## 🎯 Рекомендуемый Порядок Реализации

### Этап 1: Инфраструктура (Неделя 1-2)
1. **Автоматические бекапы** (4-5 дней)
   - Критично для безопасности данных
   - Позволит безопасно тестировать остальные функции
   - Меньше зависимостей от других модулей

2. **Редактирование тегов** (2-3 дня)
   - Быстро реализуется
   - Важно для организации контента
   - Может использоваться сразу редакторами

### Этап 2: Контент (Неделя 3-4)
3. **Файловый менеджер** (5-6 дней)
   - Улучшит работу с контентом
   - Интеграция с редактором статей
   - Нужен для загрузки ассетов темы

### Этап 3: Кастомизация (Неделя 5-8)
4. **Дизайн и оформление в настройках** (8-10 дней)
   - Самый сложный и объемный модуль
   - Требует тщательного проектирования UI/UX
   - Делать в последнюю очередь, когда все остальное стабильно

## 🛠️ Технический Стек

### Backend:
- Laravel 11.x
- PHP 8.2+
- MySQL 8.0+
- Laravel Scheduler для CRON-задач
- Laravel Storage для файлов

### Frontend:
- Blade Templates
- JavaScript (Vanilla / Alpine.js для интерактивности)
- CSS3 / Tailwind CSS (опционально)
- AJAX для асинхронных операций

### Библиотеки:
- **Файловый менеджер:** Laravel-Filemanager или custom
- **Обработка изображений:** Intervention Image
- **Архивация:** ZipArchive, TarGz
- **Цвета:** CSS Custom Properties (переменные)
- **Drag-and-drop:** SortableJS, Dropzone.js

## 📝 Дополнительные Рекомендации

### Безопасность:
- Все новые модули должны использовать middleware для проверки прав доступа
- Валидация всех входных данных
- CSRF защита для форм
- Rate limiting для операций бекапа/восстановления

### Производительность:
- Кеширование настроек темы (Cache::remember)
- Ленивая загрузка изображений в файловом менеджере
- Оптимизация SQL-запросов (eager loading)
- Очередь (Queue) для тяжелых операций (бекап, генерация миниатюр)

### UX/UI:
- Responsive дизайн для всех новых страниц
- Подтверждение для критичных действий (удаление, восстановление)
- Подсказки (tooltips) для сложных настроек
- Предпросмотр изменений в реальном времени (для темы)

### Документация:
- Создать THEME_SETTINGS_GUIDE.md с инструкциями по настройке темы
- FILE_MANAGER_GUIDE.md с описанием работы с файлами
- BACKUP_GUIDE.md с инструкциями по бекапам и восстановлению
- Видео-инструкции для редакторов (опционально)
