## 🎯 Способы Восстановления

Простое, безопасное, контролируемое.

## 📥 Вариант 1: Ручное Восстановление

### Шаг 1: Скачать Бекап

#### Через админку:
1. Откройте: `https://notame.ru/notaadmin/backups`
2. Найдите нужный бекап
3. Нажмите кнопку **"Скачать"** (💾)
4. Сохраните файл (например: `backup_full_2026-01-24_03-00-00.tar.gz`)

#### Через FTP/SSH:
```bash
# Путь к бекапам на сервере
/var/www/iq210692/data/www/notame.ru/storage/app/backups/

# Скачать через FTP клиент (FileZilla)
```

---

### Шаг 2: Распаковать Бекап

#### На локальном компьютере:
```bash
# Mac/Linux
tar -xzf backup_full_2026-01-24_03-00-00.tar.gz

# Windows (7-Zip, WinRAR)
Правой кнопкой → Извлечь в папку
```

#### Структура распакованного бекапа:
```
backup_full_2026-01-24_03-00-00/
├── database/
│   └── database.sql.gz (или database.sql)
├── files/
│   └── public/
│       └── images/
│           └── posts/ (все изображения)
├── config/
│   ├── .env
│   └── backup.php
└── manifest.json (метаданные)
```

---

### Шаг 3: Восстановить Базу Данных

#### Вариант A: Через phpMyAdmin (Проще)

1. **Распаковать дамп** (если сжат):
   ```bash
   gunzip database.sql.gz
   # Получится: database.sql
   ```

2. **Открыть phpMyAdmin:**
   - URL: `https://notame.ru/phpmyadmin/`
   - База: `iq210692_notamerurework`

3. **Импортировать:**
   - Вкладка **"Импорт"**
   - Выбрать файл: `database.sql`
   - Формат: SQL
   - Нажать **"Вперед"**

⚠️ **ВАЖНО:** Это **ПЕРЕЗАПИШЕТ** текущую БД!

#### Вариант B: Через SSH (Быстрее)

```bash
# Если есть доступ по SSH
cd /path/to/backup/

# Если сжато
gunzip database.sql.gz

# Импорт
mysql -u USERNAME -p DATABASE_NAME < database.sql

# Для notame.ru:
mysql -u iq210692_notamerurework -p iq210692_notamerurework < database.sql
```

---

### Шаг 4: Восстановить Файлы

#### Изображения (самое важное):

**Через FTP (FileZilla):**
```
Локально: backup_full_2026-01-24/files/public/images/posts/
→
На сервере: /var/www/iq210692/data/www/notame.ru/public/images/posts/
```

**Действие:** Перетащить все файлы из бекапа на сервер.

⚠️ **Опции:**
- **"Перезаписать все"** - заменить текущие файлы
- **"Пропустить существующие"** - сохранить новые файлы

#### Конфигурация (опционально):

Если нужно восстановить `.env`:
```
backup_full_2026-01-24/config/.env
→
/var/www/iq210692/data/www/notame.ru/.env
```

⚠️ **Осторожно:** `.env` может содержать старые настройки!

## 🤖 Вариант 3: Автоматический Скрипт Восстановления

Создам скрипт для автоматизации восстановления.

### Файл: `restore-backup.php`

**Расположение:** `/var/www/iq210692/data/www/notame.ru/restore-backup.php`

**Использование:**
```
https://notame.ru/restore-backup.php?backup=backup_full_2026-01-24_03-00-00.tar.gz&key=ВАSECRET_KEY&mode=preview
```

**Режимы:**
- `preview` - показать что будет восстановлено
- `database` - восстановить только БД
- `files` - восстановить только файлы
- `full` - полное восстановление

## ⚠️ ВАЖНЫЕ ПРЕДУПРЕЖДЕНИЯ

### Перед Восстановлением:

1. **✅ СОЗДАЙТЕ БЕКАП ТЕКУЩЕГО СОСТОЯНИЯ!**
   - Восстановление перезапишет данные
   - Старые данные будут потеряны

2. **Проверьте дату бекапа:**
   - Убедитесь что восстанавливаете правильную версию
   - Более новые данные будут потеряны

3. **Закройте сайт на время восстановления:**
   - Поставьте режим обслуживания
   - Или восстанавливайте ночью

### Во Время Восстановления:

- ⏱️ **Не закрывайте браузер/окно**
- 🚫 **Не перезагружайте страницу**
- ⌛ **Дождитесь завершения** (может занять 5-10 минут)

### После Восстановления:

1. **Очистите кеш:**
   ```sql
   DELETE FROM cache;
   DELETE FROM cache_locks;
   ```

2. **Проверьте все разделы сайта**

3. **Проверьте права на файлы:**
   ```bash
   chmod -R 755 public/images/
   ```

## 🆘 Решение Проблем

### Ошибка: "Файл слишком большой для импорта"

**Решение:**
1. Разбить SQL файл на части:
   ```bash
   split -l 10000 database.sql database_part_
   ```
2. Импортировать по частям

**Или:**
Увеличить лимиты в phpMyAdmin (попросить хостинг).

---

### Ошибка: "Duplicate entry" при импорте

**Решение:**
Очистить таблицы перед импортом:
```sql
SET FOREIGN_KEY_CHECKS = 0;
TRUNCATE TABLE posts;
TRUNCATE TABLE categories;
-- и т.д.
SET FOREIGN_KEY_CHECKS = 1;
```

---

### Изображения не отображаются

**Проверить:**
1. Права на папки (755)
2. Пути в БД правильные
3. Файлы действительно скопированы

**Исправить права:**
```bash
chmod -R 755 public/images/
```
