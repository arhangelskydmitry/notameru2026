# Спецификация Telegram-бота для управления проектом через Cursor Agent

## 1. Назначение

Нужно разработать Telegram-бота, который позволяет управлять разработкой проекта из Telegram-чата. Бот должен принимать текстовые, голосовые сообщения и сообщения с вложениями, понимать контекст беседы, запускать Cursor Agent для выполнения задач, вести журнал общения и безопасно работать на боевом сервере.

Бот нужен не как простой командный интерфейс, а как рабочий помощник команды: принимает задачи, объясняет статус человеческим языком, выполняет изменения в коде/документации, сообщает результат и сохраняет историю.

## 2. Основные роли

### Основной бот

Основной бот работает как разработчик/контролёр проекта.

Он должен:
- принимать задачи на разработку, документацию, диагностику и продуктовые изменения;
- запускать Cursor Agent через Cursor SDK;
- вносить изменения в кодовую базу;
- отвечать простым человеческим языком;
- не показывать пользователям task id, run id, stack trace и прочую техническую служебную информацию без необходимости;
- сохранять полный контекст переписки;
- уметь работать с голосовыми сообщениями и вложениями;
- ставить задачи в очередь, если уже выполняется другая задача.

### Дополнительный бот-наставник

Второй бот может быть консультантом, тестировщиком или продуктовым наставником.

Он должен:
- не менять код;
- анализировать продукт, UX, документацию, сценарии;
- ставить задачи основному боту;
- участвовать в режиме диалога;
- молчать, если сообщение адресовано не ему.

## 3. Пользовательский сценарий

Пользователь пишет в Telegram:

- обычное сообщение: "добавь страницу настроек";
- голосовое сообщение;
- фото/файл с подписью: "посмотри, что тут не так";
- команду: `/agent <задача>`;
- команду: `/queue`;
- команду: `/status`;
- команду: `/logs`;
- команду: `/help`.

Бот должен сразу ответить:

- "Ваше сообщение принял. Работаю над ответом."
- или "Ваше сообщение принял. Выполняю задачу."
- если задача уже выполняется: "Поставил задачу в очередь. В работе сейчас: 1. В очереди: 2."

После выполнения бот должен дать короткий человеческий отчёт:
- что сделал;
- что проверил;
- если что-то не получилось, почему;
- что можно сделать дальше.

## 4. Обработка сообщений

Бот должен слушать:

- `message:text`;
- `message:voice`;
- `message:caption`;
- `message:document`;
- `message:photo`;
- `message:video`;
- `message:animation`;
- `message:audio`;
- `message:sticker`.

### Текст

Текстовые сообщения классифицируются:

- простое общение;
- задача на разработку;
- уточнение предыдущего контекста;
- рискованное действие;
- команда.

### Голос

Голосовые сообщения нужно:
- скачать через Telegram API;
- распознать через OpenAI Whisper или другой STT;
- сохранить в журнал как `voice`;
- передать распознанный текст в общий обработчик сообщений.

### Вложения

Если вложение пришло с подписью:
- бот должен обработать подпись как обычную задачу;
- в контекст добавить описание вложения: фото, документ, видео и т.д.;
- сохранить в журнал как `attachment`.

Если вложение пришло без подписи:
- бот не должен молчать;
- должен ответить: "Вижу вложение. Напишите, пожалуйста, что с ним сделать или что проверить."

## 5. Очередь задач

Нужно реализовать очередь агентских задач.

Требования:
- одновременно выполняется только одна задача Cursor Agent;
- новые задачи становятся в очередь;
- пользователь видит количество задач в работе и в очереди;
- после завершения одной задачи автоматически запускается следующая;
- при рестарте сервиса старые `queued` и `running` задачи помечаются как `failed`, чтобы не было зависших задач.

Команда:

```text
/queue
```

Ответ:

```text
В работе сейчас: 1. В очереди: 3.
```

## 6. Журнал беседы

Нужно сохранять историю Telegram-чата в отдельные JSONL-файлы.

Каждая запись:

```json
{
  "ts": "2026-06-05T10:00:00.000Z",
  "chatId": "-100...",
  "fromId": 123,
  "username": "username",
  "direction": "in",
  "kind": "text | voice | attachment | agent_context | task_status",
  "text": "сообщение"
}
```

Журнал нужен для:
- передачи контекста Cursor Agent;
- восстановления истории;
- понимания follow-up сообщений;
- аудита работы.

Перед запуском агента бот должен добавлять в prompt последние сообщения беседы.

## 7. Cursor SDK

Для выполнения задач использовать Cursor SDK.

Логика:
- создать Cursor Agent;
- передать prompt с контекстом;
- запустить выполнение;
- слушать progress/status events;
- обновлять Telegram-сообщение со статусом;
- дождаться результата;
- сохранить результат в task store;
- отправить пользователю понятный отчёт.

Prompt должен включать:
- роль бота;
- правила общения;
- контекст последних сообщений;
- текущее сообщение пользователя;
- ограничения по безопасности;
- запрет раскрывать секреты;
- требование отвечать простым языком.

## 8. Безопасность

Нужно предусмотреть approve-flow для рискованных действий.

Рискованные действия:
- deploy;
- systemd/nginx/server операции;
- удаление файлов;
- работа с secret/token/password;
- destructive git-команды;
- force операции.

Если задача рискованная:
- бот не выполняет её сразу;
- создаёт pending approval;
- отправляет кнопки "Подтвердить" / "Отклонить";
- выполняет только после подтверждения разрешённым пользователем.

Секреты нельзя:
- выводить в чат;
- сохранять в публичные логи;
- передавать в отчётах.

### Production path и резервные копии

Основной бот notame.ru работает прямо в `WORKING_DIRECTORY`, то есть в боевой
директории проекта. Поэтому перед каждой задачей Cursor Agent обязательна
резервная копия файлов.

Требования:
- перед запуском агентской задачи создать snapshot git-visible файлов;
- сохранить `backupId` в задаче;
- после завершения задачи сохранить `changedFiles` и `diffSummary`;
- команда `/backup last` показывает последнюю резервную копию;
- команда `/diff last` показывает summary текущих изменений;
- команда `/rollback last` восстанавливает файлы, изменённые последней агентской задачей;
- `/rollback last` доступен только approver-пользователям.

## 9. Команды

Минимальный набор команд:

```text
/start
/help
/status
/queue
/tasks
/logs <taskId>
/agent <задача>
/approve <id>
/reject <id>
/chat_context
```

Дополнительно по проекту:

```text
/docs_files
/iiko_status
/iiko_incidents
/диалог
/диалог_стоп
```

Команды можно адаптировать под новый проект.

## 10. Хранилища

Использовать файловые JSON/JSONL-хранилища:

- task store;
- failed queue;
- approvals;
- event log;
- conversation logs;
- chat memory;
- sessions;
- kanban, если нужен;
- dialog mode state, если есть второй бот.

Файлы хранить в shared-директории на сервере, например:

```text
/srv/project/shared/
```

## 11. Деплой

Бот должен работать как systemd user service.

Пример сервисов:

```text
project-telegram-agent.service
project-telegram-mentor.service
```

Сервис должен:
- запускать `node dist/index.js`;
- использовать `EnvironmentFile`;
- иметь `Restart=always`;
- работать из директории приложения;
- после рестарта отправлять в известные чаты сообщение: "Агент перезапущен и готов к работе."

## 12. Переменные окружения

Минимально:

```env
TELEGRAM_BOT_TOKEN=
ALLOWED_TELEGRAM_USER_IDS=
ALLOWED_TELEGRAM_USERNAMES=
TELEGRAM_APPROVER_USER_IDS=
TELEGRAM_APPROVER_USERNAMES=
OPENAI_API_KEY=
CURSOR_API_KEY=
CURSOR_MODEL=composer-2.5
WORKING_DIRECTORY=/srv/project/current
TELEGRAM_AGENT_SHARED_DIR=/srv/project/shared
AGENT_RUN_TIMEOUT_MS=180000
MAX_AGENT_PROMPT_CHARS=6000
MAX_VOICE_DURATION_SECONDS=180
VOICE_TRANSCRIPTION_MODEL=whisper-1
AUTO_AGENT_ON_CHAT=true
```

## 13. Стиль общения

Бот должен писать по-человечески.

Правила:
- не использовать "нейросимволы" и декоративные эмодзи;
- не писать технические ID без необходимости;
- не заваливать пользователя stack trace;
- если задача выполнена, объяснять результат простым языком;
- если пользователь не программист, объяснять бизнес-смыслом;
- если задача большая, обновлять статус по ходу работы;
- если не получилось, спокойно объяснить причину и следующий шаг.

## 14. Проверки перед деплоем

Перед деплоем обязательно:

```bash
npm run typecheck
npm run build
npm run test
```

После деплоя:

```bash
systemctl --user restart project-telegram-agent.service
systemctl --user status project-telegram-agent.service
curl http://127.0.0.1:3000/health
```

Также проверить:
- бот отвечает на текст;
- бот отвечает на голос;
- бот видит вложение с подписью;
- бот не молчит на вложение без подписи;
- очередь работает;
- после рестарта нет зависших `queued/running` задач.

## 15. MVP-критерии готовности

Бот считается готовым, если:

- принимает задачи из Telegram;
- запускает Cursor Agent;
- сохраняет историю чата;
- умеет голосовые сообщения;
- умеет вложения;
- ставит задачи в очередь;
- показывает статус;
- защищает рискованные операции approval-flow;
- перезапускается через systemd;
- после рестарта сообщает в чат, что готов к работе;
- отвечает пользователю человеческим языком.
