# AGENTS.md — правила работы AI-агента в репозитории notameru2026

Проект: сетевое издание «Нота Миру» (notame.ru).
Эти правила обязательны для любого AI-агента (Cursor IDE, Cloud Agents,
Telegram-контур из `tools/telegram-cursor-agent`).
Концепция и ТЗ: `docs/CURSOR_AGENT_CONCEPT_AND_SPEC.md`.

## Состав репозитория

- корень — Laravel 12 (PHP 8.3, MySQL): CMS, API, админка notame.ru;
- `clients/macos` — SwiftUI macOS-клиент (спека: `clients/macos/docs/SPEC.md`);
- `tools/telegram-cursor-agent` — Node.js/TypeScript kit Telegram-ботов;
- `docs/` — актуальная документация; `*.md` в корне — в основном исторические отчёты.

## Рабочий процесс

1. Сначала читай существующий код, потом пиши изменения. Следуй паттернам,
   которые уже есть рядом, а не «идеальным» абстракциям.
2. Перед крупными изменениями (миграции схемы, рефакторинг модуля, новые
   зависимости) — сначала короткий план, потом код.
3. Код и идентификаторы — на английском. Комментарии — на русском и только там,
   где поясняют неочевидное. Общение с пользователем — на русском.
4. Не добавляй зависимости без необходимости; версии — только через
   composer/npm, не вручную в lock-файлах.

## Конвенции Laravel-части

- Бизнес-логика — в `app/Services` (см. `SeoGeneratorService`, `BackupService`).
  Контроллеры тонкие.
- Глобальные хелперы — в `app/Helpers`, регистрация в `composer.json` →
  `autoload.files`.
- Миграции аддитивные, имена по шаблону `YYYY_MM_DD_HHMMSS_verb_subject.php`
  (см. `database/migrations`). Не редактируй уже применённые миграции.
- Таблицы контента имеют префикс `laravel_` (`laravel_posts`,
  `laravel_categories` и т.д.) — сохраняй его.
- Шаблоны — Blade в `resources/views`; админка — MoonShine (`app/MoonShine`).

## Проверки перед сдачей работы

Laravel:

```bash
vendor/bin/pint --test
php artisan test
```

Node-части (`tools/telegram-cursor-agent`):

```bash
npm run typecheck && npm run build && npm run test
```

Если окружение не позволяет выполнить проверку (нет БД, нет зависимостей) —
честно укажи это в отчёте/PR, не утверждай, что проверено.

## Git и PR

- Ветки: `cursor/<краткое-описание-задачи>` от `main`, всё в нижнем регистре.
- Один логический результат — один коммит с понятным сообщением.
- PR описывает: что сделано, как проверено, какие риски/что осталось.
- Не коммить: `.env`, дампы БД, `*.tar.gz`, `node_modules`, `vendor`, `dist`,
  бэкапы, сгенерированные отчёты.

## Запрещено без явного подтверждения человека

- деплой на production и `php artisan migrate` на боевой БД;
- systemd/nginx/PM2/cron операции;
- удаление файлов и данных;
- `composer install/update`, `npm install` на сервере;
- `git reset --hard`, `git clean`, `git push --force`;
- любые операции с секретами, токенами, паролями, содержимым `.env`.

## Запрещено всегда

- выводить секреты в чат, логи, коммиты, отчёты;
- выдумывать факты о проекте — если контекста не хватает, задай короткий
  уточняющий вопрос;
- править редакционный контент (тексты статей) — это зона редакции и
  notame-agent, а не кодового агента.

## Стиль отчётов (Telegram-контур)

- простой человеческий язык, без task id, run id, stack trace;
- без декоративных эмодзи и «нейросимволов»;
- структура: что изменилось → что проверено → практический результат → что
  нужно от людей дальше.
